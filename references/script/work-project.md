# 工作项目汇报

## 进度汇报

目标、阶段结果、卡点、下一步，四段讲完。

- 阶段结果用里程碑、上线记录、使用数据说话，不要用「进展顺利」。
- 卡点写清楚影响、当前处理方式、需要谁决定什么、资料里已经约定的时间。
- 面向负责人时先说影响和需要拍板的选项，细节放后面。

## 成果验收或技术评审

从业务场景、交付目标或要评审的决定切入，按听众关心的问题组织证据。

- 面向负责人：突出影响、成本、需要确认的决定。
- 面向技术同事：交代关键机制、方案取舍、验证环境、适用条件。
- 有指标时交代统计范围、时间窗和比较基准，区分测试结果、试运行和生产结果。
- 已交付、待验证、后续安排分三段说，不要混在一起。

## 追问准备

按 [问答备稿](qa.md) 写。工作场景的高频问题：成本、稳定性、回滚、监控、谁维护、能不能复用到别的业务。

面向外部听众时，先核对材料的公开范围。
