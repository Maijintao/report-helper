# 学生课程设计汇报

## 中期检查

中期只讲三件事：做到哪了、卡在哪、下一步怎么验证。按这条线排，五到七段就够，不要写成期末稿的缩小版。

1. 一句交代课程任务、团队分工、自己负责哪块
2. 进度用数字说：多少功能、多少题、覆盖哪些场景、多少测试用例
3. 挑一个能代表当前工作量的例子，讲清输入、操作、结果
4. 卡点具体到「哪个环节、影响什么」
5. 下一步怎么验证，带时间点
6. 收尾，交给下一位

进度数字配单位和范围。课程要求的交付项可以直接当组织线索。

## 期末答辩

按 [稿件流程](workflow.md) 的十四段骨架走，重点在两处：

- **界定范围**：三门课或多组做同一个题时，先说清哪部分不展开，把时间留给自己的增量。
- **边界**：主动交代哪些没验证、哪些只在特定条件下成立。老师最常追问的就是这块，先说比被问出来强。

演示类项目从使用场景进：先跑一遍给人看，再讲怎么实现。数据或评测类项目从一项结果进：先给数字，再讲怎么测出来的。

讲完机制要交代实际验证范围。多人汇报时，交接句说明下一位讲什么。

## 追问准备

按 [问答备稿](qa.md) 写。课程答辩的高频问题集中在这几类：

- 这个功能是你做的还是组里做的
- 为什么选这个方案，别的方案不行吗
- 结果怎么复现，换台机器还能跑吗
- 哪些情况没测过
- 如果数据量再大十倍会怎样
