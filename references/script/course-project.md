# 学生课程设计汇报

## 中期检查

中期只讲三件事：做到哪了、卡在哪、下一步怎么验证。按这条线排，五到七段就够，不要写成期末稿的缩小版。

1. 一句交代课程任务、团队分工、自己负责哪块
2. 进度用数字说：多少功能、多少题、覆盖哪些场景、多少测试用例
3. 挑一个能代表当前工作量的例子，讲清输入、操作、结果
4. 卡点具体到「哪个环节、影响什么」
5. 下一步怎么验证，带时间点
6. 收尾，交给下一位

进度数字配单位和范围。课程要求的交付项可以直接当组织线索。

## 期末答辩

按 [稿件流程](workflow.md) 选择主线，用一个代表性案例或验证结果说明团队的主要贡献。多组做同一题时，把时间留给本组的设计决定、实现与证据。

演示类项目可以从使用场景进入，用同一个操作说明关键机制和验证结果。评测类项目可以从一项结果进入，交代怎么测、在什么范围成立。多人汇报时，交接句交代下一位负责的内容。

## 追问准备

按 [问答备稿](qa.md) 写。课程答辩的高频问题集中在这几类：

- 这个功能是你做的还是组里做的
- 为什么选这个方案，别的方案不行吗
- 结果怎么复现，换台机器还能跑吗
- 哪些情况没测过
- 如果数据量再大十倍会怎样
