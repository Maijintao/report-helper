# 稿件流程

逐字稿采用可以直接朗读的完整句子，按讲述内容分段。页码、操作、换人等舞台提示与朗读正文分开。

## 选定讲述线索

从项目资料和用户当次补充的信息收集证据。确定听众最需要记住的一个判断，以及什么画面、数据或实例能支撑它。按汇报目的选择组织方式。

- 演示类项目可以从一次操作或一次故障讲起。沿同一案例讲关键机制，最后用演示结果回答开场的问题。
- 成果验收可从交付目标讲起。按验收项给出完成结果、验证方式和适用范围。
- 技术评审可从需要做的决定讲起。集中讲相关约束、方案依据和验证结果。
- 进度汇报围绕阶段结果、正在处理的问题与下一项验证展开。

自我介绍、背景、术语解释、限制条件和交接句按听众与任务选用。在证据旁说明会影响判断的适用范围。准备问答时，把供追问的源码说明和额外数据放入 [问答备稿](qa.md)。

## 安排时间和过渡

按 [时长与字数预算](presets.md) 分配开场、讲述、演示、换人和缓冲时间。需要配 HTML 时，按证据所在的页面安排讲述，把页码或 `[翻页]` 单独放在相关段落之前。演示提示写明实际操作和预期画面。团队汇报的交接句交代下一位的讲述内容。

每段推进一个意思，用前后内容的关系过渡。术语保留原名，首次出现时交代在当前项目里的作用。数字旁说清单位、统计范围和比较基准。用可读的句子说明证据怎样支持判断。

## 交付前核对

核对图表、页面和讲稿使用的数据与术语，确保数字可追溯到用户资料。按讲述速度、演示和交接时间估算总时长，有实际彩排时间时以实测为准。超时优先压缩重复解释和次要背景。更换录屏或演示流程时，同步更新提示与时间安排。
