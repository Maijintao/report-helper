# 稿件流程

逐字稿是能直接念出来的话，不是提纲，也不是把页面文字念一遍。按意思分段，不按页分段，正文里不写页码。

## 第一步：攒素材

先把资料里的东西堆进一个文件，允许乱：项目日志、测试记录、旧稿、组会记录、自己想到的句子。这个阶段不组织语言，只收信息点，碎片、括号补充、错别字都留着。

素材至少要凑齐五样：

- 一句话结论
- 三到五个能撑住这句话的证据，优先要数字
- 一个能代表工作量的具体例子
- 一条确实做不到的边界
- 一个别人最容易误解的地方

素材不够就别急着写，写出来一定是空话。

## 第二步：定三句话

动笔前先把三句话写在稿子最上面，定不下来就不要往下写。

1. **一句话结论**：这次汇报最想让人记住的那一句。
2. **一句话范围**：不展开什么，重点讲什么。例如「三个组做的是同一套复刻，所以我不展开复刻过程，重点讲我们在复刻基础上解决的问题」。
3. **一句话交付**：听众听完能带走什么，一个判断、一个方法或者一个数字。

第二句最见功力。不说清不展开什么，稿子就会变成流水账。

动笔前按 [时长与字数预算](presets.md) 把正文字数算出来，后面写每一段都对着这个数删。

## 第三步：排段落

按下面十四段排，按场景删减，但第 2、3、12 段不能省。

1. 自报家门，说清自己讲哪一部分
2. 一句话结论
3. 界定范围：不展开什么
4. 问题从哪来：现实约束、原始需求
5. 用户真正要解决的问题
6. 我们做了什么，一句话
7. 概念解释：这个名词在本项目里指什么
8. 分点展开：第一类、第二类、第三类
9. 澄清一个容易被误解的地方
10. 落地细节：具体怎么接进系统
11. 举一个例子，把流程走完
12. 边界：什么情况下做不到，哪些还没验证
13. 总结：复述结论，不重复细节
14. 收尾，交给下一位

## 第四步：写成能念的话

- 一段只推进一步。段落之间用过渡句接，不要靠小标题硬切。
- 每段第一句先给结论，后面再讲机制。
- 讲一个技术点写三句：它是什么（一句人话）、为什么需要它（什么约束逼出来的）、它具体怎么做。
- 一句话只说一件事，超过 30 个字就拆。
- 术语保留原名，第一次出现补一句它在这个项目里干什么。
- 数字带口径：多少、什么范围、什么时候、和谁比。
- 用「不是 A，而是 B」划界限，这是信息量最大的句式。
- 括号里放可讲可不讲的补充，现场自己决定讲不讲。
- 不写「我们主要做了以下三方面工作」「效果比较理想」这类空话。

## 第五步：自检

- 念一遍并掐表。中文按每分钟 220 字估，实测偏差超过 20% 的段落先删句子，不删信息。
- 逐段问两句：第一句是不是结论？这段有没有在复述页面上的字？
- 数字能不能追溯到资料。取不到的标「待确认」，不要编。
- 边界段有没有具体到「哪种情况下做不到」，而不是「还有优化空间」。
- 问答备稿单独写，按 [问答备稿](qa.md) 来。

需要配 HTML 汇报页时，在段落之间单独一行写页码或 `[翻页]`，不要写进句子。没有页面就不写页码。
